# Task: Update `docs/whats_next_script.md` with hook documentation

## Description

Update `docs/whats_next_script.md` to document the CIP-0017 local hook system so users
can discover and use the extension mechanism. The documentation should follow the existing
style of the file.

## Acceptance Criteria

- [ ] A new "Extending whats-next with Local Hooks" section is added to `docs/whats_next_script.md`
- [ ] Section explains when to use local hooks (project-specific status, domain checks)
- [ ] Section documents how to activate the extension (create `.vibesafe/whats_next_local.py`)
- [ ] Documents `get_local_sections(context)`: signature, `context` dict keys, return format (2-tuple and 3-tuple), `position` values (`"before"` / `"after"`)
- [ ] Documents `get_local_next_steps(context)`: signature, return format (plain str, `("high", …)`, `("low", …)`)
- [ ] Includes a short worked example (inline code block) showing both hooks in use
- [ ] Mentions the template stub at `templates/.vibesafe/whats_next_local.py.example`
- [ ] Notes that errors in local hooks are caught and reported as warnings without crashing `whats-next`

## Implementation Notes

Add the new section after the existing "Command Line Options" section and before any
"Related" / "References" section. Keep the tone consistent with the rest of the file
(concise, example-driven).

The context dict key table from CIP-0017 can be reproduced directly:

| Key | Type | Description |
|-----|------|-------------|
| `git_info` | `dict` | Output of `get_git_status()` |
| `cips_info` | `dict` | Output of `scan_cips()` |
| `backlog_info` | `dict` | Output of `scan_backlog()` |
| `requirements_info` | `dict` | Output of `scan_requirements()` |
| `args` | `argparse.Namespace` | CLI arguments |
