# Task: Document CIP-backlog coverage check in validation docs

## Description

Update the validator documentation to describe the new check so users
understand what the warning means and how to suppress it.

Target file: `docs/source/whats_next_script.md` (or a dedicated validator
doc page if one exists).

Add a new entry under the "Validation Types" or equivalent section:

**CIP-Backlog Coverage Check** (`--no-cip-backlog-check`)
- What it checks: every Accepted/In-Progress CIP has at least one backlog task referencing it
- Severity: warning (escalates to error with `--strict`)
- How to fix: create backlog tasks with `related_cips: ["XXXX"]` pointing to the CIP
- How to skip: pass `--no-cip-backlog-check` to the validator

## Acceptance Criteria

- [ ] Documentation describes the check, its severity, and the opt-out flag
- [ ] Example warning message is shown so users can recognise it
- [ ] "How to fix" guidance references the VibeSafe backlog workflow
