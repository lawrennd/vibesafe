# CIP-0018: Global Claude Code Context File (~/.claude/CLAUDE.md)

## Summary

VibeSafe already generates per-project AI context files (`CLAUDE.md`, `AGENTS.md`, `.cursor/rules/`). This CIP adds generation and maintenance of a **global** `~/.claude/CLAUDE.md` file, giving Claude Code cross-project context about VibeSafe conventions and the user's overall project setup.

This addresses the Claude Code side of [REQ-000C](../requirements/req000C_ai-assistant-framework-independence.md): VibeSafe should work seamlessly with Claude Code, not just Cursor.

## Motivation

Claude Code determines project scope from the git root and reads context from `CLAUDE.md` files at three levels:

1. `~/.claude/CLAUDE.md` — **global**, applies to all Claude Code sessions
2. Parent-directory `CLAUDE.md` files (traversed upward from project root)
3. `<project-root>/CLAUDE.md` — per project (VibeSafe already handles this)

VibeSafe handles level 3 well: `install-minimal.sh` generates `CLAUDE.md` and `AGENTS.md` in each project. But level 1 is unaddressed. Without a global `~/.claude/CLAUDE.md`, Claude Code has no cross-project understanding of:

- What VibeSafe is and how to read its file structures
- That the user works across multiple VibeSafe-managed repos
- The user's overall development context (languages, tools, conventions)

This parallels the existing Cursor global rules support, completing the Claude Code parity needed for REQ-000C.

## Detailed Description

### How `~/.claude/CLAUDE.md` works in Claude Code

Claude Code reads `CLAUDE.md` files in order from global → local, merging the context. The global file at `~/.claude/CLAUDE.md` is read for **every session**, regardless of which project is open. It is the equivalent of a "user-level system prompt" for Claude Code.

### What the global file should contain

The generated `~/.claude/CLAUDE.md` should explain:

1. **VibeSafe overview** — what the system is, what `cip/`, `backlog/`, `requirements/`, and `tenets/` directories mean, and how to navigate them
2. **Key conventions** — hexadecimal CIP numbering, date-stamped backlog tasks, YAML frontmatter fields, status workflows
3. **Cross-project awareness** — that the user may work across multiple VibeSafe-managed repos and that each has its own `CLAUDE.md` for project-specific context

This is intentionally brief — detailed per-project context lives in each repo's `CLAUDE.md`. The global file is the "what is VibeSafe" orientation that shouldn't need repeating in every project.

### What it should NOT contain

- Project-specific tenets or requirements (those belong in per-project `CLAUDE.md`)
- User-specific credentials or sensitive information
- Verbose documentation that duplicates the VibeSafe README

### Generation approach

Two options:

**Option A: Generate during `install-minimal.sh`**
- When VibeSafe is installed in a project, also create/update `~/.claude/CLAUDE.md`
- Pro: automatic, no extra step
- Con: runs on every install, needs idempotent merge logic if the user has customised the file

**Option B: Separate `install-claude-global.sh` script**
- A one-time setup script the user runs explicitly
- Pro: explicit, no risk of overwriting user customisations
- Con: requires manual step; user may forget

**Recommended: Option A with a guarded update**
- Check if `~/.claude/CLAUDE.md` exists
- If not: create it with the VibeSafe global template
- If yes: check for a `# VibeSafe` section marker; update only that section, preserving user content above/below
- Same idempotent pattern as VibeSafe's existing `CLAUDE.md`/`AGENTS.md` generation

### File structure

```markdown
<!-- VibeSafe-managed section - updated by install-minimal.sh -->
# VibeSafe Context

VibeSafe is a project management framework for AI-assisted development.
It organises project knowledge into four components:

- `tenets/` — Guiding principles (WHY)
- `requirements/` — Desired outcomes (WHAT)
- `cip/` — Code Improvement Plans (HOW)
- `backlog/` — Implementation tasks (DO)

## Conventions

- CIPs are numbered in hexadecimal: `cip0001.md`, `cip000A.md`, `cip0010.md`
- Backlog tasks are dated: `YYYY-MM-DD_short-description.md`
- All files use YAML frontmatter with `status`, `id`, and `created` fields
- Status workflows: Proposed → Accepted → In Progress → Implemented → Closed

## Working with VibeSafe repos

Each VibeSafe-managed repo has its own `CLAUDE.md` with project-specific context.
Run `./whats-next` in any repo to see current priorities.
<!-- End VibeSafe-managed section -->
```

### Relationship to existing CIP-0012

CIP-0012 introduced `CLAUDE.md` and `AGENTS.md` generation for AI assistant independence. This CIP extends that work to the global level for Claude Code, applying the same pattern one level up.

## Implementation Plan

1. **Add `~/.claude/` directory creation** to `install-minimal.sh`:
   - Check for `~/.claude/` and create if absent
   
2. **Create VibeSafe global template** at `templates/claude-global/CLAUDE.md`:
   - Short VibeSafe orientation (what it is, conventions, how to navigate)
   - Delimited with `<!-- VibeSafe-managed section -->` markers

3. **Add idempotent update logic** to `install-minimal.sh`:
   - If `~/.claude/CLAUDE.md` does not exist: copy template
   - If it exists: replace content between the section markers; preserve everything outside them

4. **Add to `whats-next`** optional check:
   - Warn if `~/.claude/CLAUDE.md` does not contain a VibeSafe section
   - Suggest running the installer to add it

5. **Test**:
   - Fresh install: `~/.claude/CLAUDE.md` created correctly
   - Reinstall: VibeSafe section updated, user content preserved
   - `whats-next` warning appears when section is absent

## Backward Compatibility

- Does not affect existing per-project `CLAUDE.md` generation
- Users without Claude Code installed are unaffected (script checks for `~/.claude/` directory or creates it)
- Users who have customised `~/.claude/CLAUDE.md` retain their content outside the VibeSafe section markers

## Testing Strategy

- Test on a machine with no `~/.claude/CLAUDE.md` — file created
- Test on a machine with a pre-existing `~/.claude/CLAUDE.md` — VibeSafe section added, user content preserved
- Test idempotency: run installer twice — file unchanged on second run
- Test `whats-next` warning: rename `~/.claude/CLAUDE.md` to something else, confirm warning appears
