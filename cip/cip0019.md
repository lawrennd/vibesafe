## Summary

Add a cross-component validation check to `validate_vibesafe_structure.py`
that warns when a CIP with status `Accepted` or `In Progress` has no
corresponding backlog tasks pointing to it via `related_cips`.

This addresses the observed pattern where agents (and humans) implement CIPs
directly without first creating the backlog tasks the VibeSafe workflow requires.
It implements the "Status Consistency" clause of REQ-0006.

## Motivation

The VibeSafe workflow mandates:

> *CIP Accepted → break down into backlog tasks → In Progress → Implement*

In practice, AI agents frequently move a CIP to `In Progress` (or jump straight
to coding) without ever creating any backlog tasks. The gap is invisible until
someone manually inspects the CIP list. Currently `whats-next` *suggests* creating
tasks but does not *enforce* it. A validation check run at commit time catches
the gap automatically — on every commit — before code drifts further from the plan.

## Detailed Description

### What the check does

After all per-file validations have run, a new cross-component function scans:

1. All CIP files with `status: Accepted` or `status: In Progress`
2. All backlog task files, collecting every value listed in any `related_cips` field

For any CIP in group 1 whose `id` appears in no `related_cips` list in group 2,
emit a validation **warning** pointing to the CIP file.

### Severity: warning, not error

REQ-0006 says "Status Consistency" findings should be "Warnings, not hard
failures." A warning shows in yellow on the console and appears in `whats-next`
output but does not block commits (exit code 0). This gives teams flexibility —
e.g. a tiny CIP with a single commit may legitimately skip formal backlog tasks —
while still making the omission clearly visible.

Teams that want stricter enforcement can pass `--strict` to the validator, which
already escalates all warnings to errors and exit code 1.

### ID normalisation

CIP ids in frontmatter are short hex strings like `"0017"`. Backlog
`related_cips` values should match this format. The check compares
`str(cip_id).strip()` with `str(ref).strip()` to handle minor whitespace
variation. No further normalisation is needed because the existing
`validate_cross_references` function already enforces that `related_cips`
entries are valid CIP ids.

### New function signature

```python
def check_cip_backlog_coverage(root_dir: str, result: ValidationResult) -> None:
    """Warn when an Accepted or In-Progress CIP has no backlog tasks.

    Scans all CIPs with status 'Accepted' or 'In Progress' and checks
    whether at least one backlog task references each CIP via related_cips.
    Implements the CIP→backlog workflow traceability check (CIP-0019).
    """
```

Called in `main()` as Step 6, after `check_governance_drift` (Step 5):

### Opt-out flag

A `--no-cip-backlog-check` flag is added so teams or scripts can opt out,
consistent with the existing `--no-governance-drift` flag pattern.

### Core algorithm

```python
def check_cip_backlog_coverage(root_dir: str, result: ValidationResult) -> None:
    # 1. Collect active CIPs (Accepted or In Progress)
    active_cips = {}   # id → (title, file_path)
    for file_path in find_component_files(root_dir, 'cip'):
        fm = extract_frontmatter(file_path)
        if fm and fm.get('status') in ('Accepted', 'In Progress'):
            cip_id = str(fm.get('id', '')).strip()
            if cip_id:
                active_cips[cip_id] = (fm.get('title', 'Untitled'), file_path)

    if not active_cips:
        return

    # 2. Collect all CIP ids referenced by any backlog task
    covered_ids = set()
    for file_path in find_component_files(root_dir, 'backlog'):
        fm = extract_frontmatter(file_path)
        if fm:
            for ref in fm.get('related_cips', []):
                covered_ids.add(str(ref).strip())

    # 3. Warn for each uncovered active CIP
    for cip_id, (title, file_path) in sorted(active_cips.items()):
        if cip_id not in covered_ids:
            result.add_warning(
                f"CIP '{cip_id}' ({title}) is Accepted/In Progress but has "
                "no backlog tasks. Break it down into backlog tasks before "
                "implementing (VibeSafe workflow: Accepted → backlog tasks → "
                "In Progress).",
                file_path,
            )
```

## Backward Compatibility

The check emits warnings only (exit code 0). Existing repositories with active
CIPs and no backlog tasks will see new warnings in `./whats-next` output and at
commit time, but commits will not be blocked unless `--strict` is in use.
The `--no-cip-backlog-check` flag provides a clean opt-out.

## Testing Strategy

Use the existing `tmp_path`-style fixture pattern in
`tests/test_validate_vibesafe_structure.py`. Create minimal CIP and backlog
YAML files in a temporary directory tree for each scenario listed in the
Implementation Plan.
